# 다음 개선 루프

## 이번 사이클

원본 ZIP의 일반 소스 복원, typed Dio/multiline import, 수집 우선순위, 압축 해제 전 ZIP 예산, 누락 집계, 8노드 전체 화면, 반복 가능한 verify.py와 GitHub Actions를 추가했다. 실제 성공/실패 결과는 EXECUTION_VALIDATION.md에서 확인한다.

## 우선순위

**P1: 실제 결과의 정확도.** GitHub 48파일 제한으로 빠지는 핵심 파일을 평가하고, entrypoint와 import 기반 수집으로 발전시킨다. Hono router prefix와 path parameter, Dart 문자열 보간을 보완한다. 서버 origin을 증명하지 못한 연결은 계속 candidate다.

**P2: 더 깊은 분석.** 언어별 AST adapter를 검토하고 파일 단위 지도에서 직접 함수 호출 근거로 확장한다. 함수명 나열을 호출 관계로 오해하게 만들지 않는다.

**P2: 큰 그래프 탐색.** 검색, 접기, +N hidden 표시와 기능별 경로 선별을 실제 저장소 결과로 평가한다. 첫 화면은 계속 전체 기술 계층을 우선한다. 화면의 정적인 프로토타입 배지(v0.1)를 health 버전에 연결하는 작은 UI 개선도 남아 있다.

## 고정 절차

실패 로그 → 재현 테스트 → 최소 수정 → verify.py → Actions 로그 → 실행/수정/개선 Markdown 갱신.

자동 검사와 자동 수정은 다르다. 무제한 자기수정, 대상 저장소 코드 실행, 비공개 저장소 접근, 유료 호출, 운영 배포는 포함하지 않는다. 미실행·환경 차단·부분 분석을 성공이나 완전 분석으로 바꾸지 않는다.
